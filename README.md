# SunRiver website (Netlify build)

Static site generated by `build.py` and deployed by Netlify on every push to `main`.

- **Content:** floor plans, homes for sale and Bucketlist Living posts are read at build time from the SunRiver Sanity CMS (project `ib6s13lu`, dataset `production`). Edit content in Sanity, then trigger a Netlify deploy to publish it.
- **Pages:** `sitegen/pages_main.py` (hand-built pages) and `sitegen/pages_cms.py` (CMS pages). Shared header, footer and form live in `sitegen/lib.py`.
- **Styles and scripts:** `assets/styles.css`, `assets/site.js`.
- **Media:** images and fonts from the developers' Vercel build are copied into `/media/v` during the Netlify build. CMS images load from the Sanity CDN.

Run locally: `python3 build.py` then serve `dist/` (for example `cd dist && python3 -m http.server`). Without network access it falls back to the snapshots in `data/`.

## Deploying on Vercel (production)

1. In Vercel: Add New > Project > import the GitHub repo `adamencore/sunriverdev`.
2. Framework preset: Other. Everything else is read from `vercel.json`:
   install `python3 -m pip install -r requirements.txt`, build `python3 build.py`, output `dist`,
   plus the old-URL redirects, the `/cdn-img` proxy and cache headers.
3. Deploy, then add the domain (sunriver.com) under Settings > Domains when ready to launch.

Every push to `main` rebuilds the site. The build reads floor plans, listings and posts from Sanity
(project ib6s13lu) and falls back to the snapshots in `data/` if Sanity is unreachable.
Images borrowed from the earlier dev sites are committed under `media/` (see `.github/workflows/vendor-media.yml`),
so the build does not depend on sunriver-website.vercel.app or sunriverdev.netlify.app.

Note: the Netlify-only files (`netlify.toml`, `dist/_redirects`) are ignored by Vercel and harmless.
