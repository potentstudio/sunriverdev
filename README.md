# SunRiver website (Netlify build)

Static site generated by `build.py` and deployed by Netlify on every push to `main`.

- **Content:** floor plans, homes for sale and Bucketlist Living posts are read at build time from the SunRiver Sanity CMS (project `ib6s13lu`, dataset `production`). Publishing a post, floor plan or home listing in Sanity rebuilds the site by itself, usually within a minute (a Sanity webhook named "Rebuild website on publish" calls a Vercel deploy hook).
- **Pages:** `sitegen/pages_main.py` (hand-built pages) and `sitegen/pages_cms.py` (CMS pages). Shared header, footer and form live in `sitegen/lib.py`.
- **Styles and scripts:** `assets/styles.css`, `assets/site.js`.
- **Media:** images and fonts from the developers' Vercel build are copied into `/media/v` during the Netlify build. CMS images load from the Sanity CDN.

Run locally: `python3 build.py` then serve `dist/` (for example `cd dist && python3 -m http.server`). Without network access it falls back to the snapshots in `data/`.

## Deploying on Vercel (production)

1. In Vercel: Add New > Project > import the GitHub repo `potentstudio/sunriverdev`.
2. Framework preset: Other. Everything else is read from `vercel.json`:
   install `python3 -m pip install --break-system-packages -r requirements.txt` (Vercel's Python is
   managed by uv and refuses a plain `pip install`), build `python3 build.py`, output `dist`,
   plus the old-URL redirects, the `/cdn-img` proxy and cache headers.
3. Deploy, then add the domain (sunriver.com) under Settings > Domains when ready to launch.

Every push to `main` rebuilds the site. The build reads floor plans, listings and posts from Sanity
(project ib6s13lu) and falls back to the snapshots in `data/` if Sanity is unreachable.
Images borrowed from the earlier dev sites are committed under `media/` (see `.github/workflows/vendor-media.yml`),
so the build does not depend on sunriver-website.vercel.app or sunriverdev.netlify.app.

Note: the Netlify-only files (`netlify.toml`, `dist/_redirects`) are ignored by Vercel and harmless.

## Forms, tracking and ad landing pages

- **Forms** post to the SunRiver HubSpot portal (242537243), into the same forms the old sunriver.com embedded. The form ids,
  thank-you lines and ad conversions are in `HS_FORMS`, `HS_THANKS` and `HS_ADS` at the top of `sitegen/lib.py`; the
  submit code is the "Forms" block in `assets/site.js`. Field `name`s are HubSpot contact property names. HubSpot only accepts
  a submission from a domain listed under Settings > Tracking & Analytics > Tracking Code > Advanced Tracking > Additional site
  domains. From any other host (a preview, sunriverdev.vercel.app unless it is added there) the form still shows its thank-you,
  but HubSpot files the submission under the form's Blocked Submissions as "Unregistered Site Domain" and creates no contact.
- **Email signup card**: the small "Stay Connected" card that slides into the bottom right corner 15 seconds after a page
  loads (700px and wider; closing it or signing up keeps it away for 30 days). The markup is `signup_card()` in
  `sitegen/lib.py`, the timing is the "Email signup card" block at the end of `assets/site.js`, the styles are at the end
  of `assets/styles.css`. It posts to the HubSpot form `HS_FORMS["popup"]`. It replaces the large centred popup that
  was a HubSpot CTA; while that CTA is still published in HubSpot the card stays hidden so visitors never get both.
- **Tracking** (`TRACKING` in `sitegen/lib.py`): Google Tag Manager, Google Ads, Google Analytics, HubSpot, Microsoft Ads and
  the Meta pixel, the same ids as the old site. They load only on sunriver.com. To test elsewhere, run
  `localStorage.setItem("sr_track", "1")` in the browser console and reload.
- **Ad landing pages**: `/firelight-bing` (Microsoft Ads) and `/discovery-villas-meta` (Meta ads) are built in
  `sitegen/pages_main.py`, each with its own HubSpot form.
- **Old blog addresses**: the 220 or so redirects near the top of the blog rules in `vercel.json` map old Squarespace post
  URLs to the same post's new address. They must stay above the catch-all `/bucketlist-living/:path*` rule.

## Images

- **Every `<img>` goes through `img()` in `sitegen/lib.py`.** For an image stored in this repo (`media/`, `assets/img/`) it
  adds `width` and `height`, a `?v=` content hash, and on Vercel a `srcset` through Vercel Image Optimization
  (`/_vercel/image`), so phones get a phone-size AVIF or WebP. The allowed widths and quality are under `images` in
  `vercel.json` and must match `IMG_WIDTHS` and `IMG_QUALITY` in `lib.py`. Off Vercel the plain file is used.
- **How wide an image is shown** comes from the `IMG_SIZES` table in `lib.py`, keyed by the class of the image's container.
  A new grid or card layout should get a line there (or pass `sizes=` to `img()`), otherwise it is treated as full width.
- **The page's main image** (the hero) is the only one with `fetchpriority="high"`; it also gets a preload link. Use
  `priority=True` on `img()` or `simg()` for a page whose top image is not a `fah-hero-img`. Everything else is lazy.
- **Menu photos** in the Life at SunRiver dropdown carry `data-src` and load the first time someone goes to open the menu.
- **Adding photos:** keep them under 400 KB. `python3 tools/compress_media.py` shrinks anything new in `media/` or
  `assets/img/` in place (see the notes at the top of that file). It is run by hand, not by the build.

## Search basics (sitemap, canonical tags, share images, schema markup)

`sitegen/seo.py` runs at the end of the build and adds to every page: a canonical link on `https://www.sunriver.com`
(`SITE_URL`), Open Graph and Twitter tags with a 1200x630 share photo, and schema markup (the business on the homepage,
About and Contact; breadcrumbs on inner pages; `BlogPosting` on posts; `FAQPage` on `/faq`). It also writes
`/sitemap.xml` and `/robots.txt`.

- **Share photo**: floor plans, listings and posts use their own first photo. Every other page uses
  `assets/img/share.jpg`.
- **Hidden pages**: paths in `NOINDEX` (the two `-v2` drafts, the two ad landing pages and the 404 page) get a
  `noindex` tag and are left out of the sitemap. They still open for anyone with the link. Remove a path from the set
  when the page should be found on Google.
- **After launch**: submit `https://www.sunriver.com/sitemap.xml` in Google Search Console.

## The Studio (editing screen for Sanity content)

`studio/` is the Sanity Studio for this site's content: Bucketlist Living posts, floor plans and home listings. It is
separate from the website build (Vercel ignores it). Its address is https://sunriverdev.sanity.studio.

- Change the editing screens in `studio/src/` (field definitions in `schemaTypes/`, the sidebar in `structure/`).
- Publish a new version with `cd studio && npm install && npm run deploy`. That needs a Sanity login or token allowed
  to deploy Studios (an Editor token cannot).
- The document types grouped under "Not used by the website" were made for the earlier Next.js prototype. The site
  does not read them.
